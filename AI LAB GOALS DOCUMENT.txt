PROJECT PURPOSE
------------------------------------------------------------

AI Lab is a locally running, privacy-first AI system designed to act as an autonomous, controllable development and personal assistance environment capable of:

- interpreting and decomposing complex user goals
- autonomously building, repairing, and extending tools, agents, and sub-systems
- executing end-to-end workflows including creative production (e.g. script-to-movie)
- delegating heavy compute tasks to remote resources while keeping sensitive data local
- maintaining and optimizing the user's local PC environment
- handling personal tasks involving sensitive data (finances, schedules, documents, etc.)
- generating revenue-enabling outputs (websites, apps, games, content, research)
- evolving toward recursive self-improvement under strict manager control

The system must remain:
- transparent and inspectable
- strictly controllable by Bryan
- understandable and maintainable
- modular and extensible
- secure and privacy-preserving (sensitive data never leaves the local machine without explicit encrypted delegation)

------------------------------------------------------------
CORE GOALS
------------------------------------------------------------

1. LOCAL AUTONOMOUS AI LAB
Create a self-contained, local-first AI system capable of managing tasks, reasoning about goals, executing work, and evolving its capabilities with minimal external dependency.

2. LOCAL AI INFRASTRUCTURE WITH REMOTE BURSTING
Primarily operate locally using local models (Ollama, LocalAI, etc.) for all decision-making, planning, validation, and sensitive operations.
Delegate GPU-intensive tasks (image/video/audio generation, large model inference) to secure remote pods (RunPod, Modal, Vast.ai, etc.) only when necessary, under manager approval.

3. MANAGER-CENTRIC MULTI-AGENT SYSTEM
Orchestrated by a central Manager responsible for:
- goal interpretation
- planning and decomposition
- workflow execution
- agent/tool/sub-system coordination
- result verification and validation
- repair enforcement
- termination decisions
- final answer production
- veto of invalid LLM outputs
- sensitive data boundary enforcement

4. AGENT ECOSYSTEM
Develop specialized reasoning agents, including but not limited to:
- code_agent (tool/agent creation & repair)
- tester_agent (strict validation)
- planner_agent
- researcher_agent
- system_maintenance_agent
- sub-system specific agents (e.g. movie_writer_agent, video_renderer_agent)

Agents perform complex reasoning, workflows, and delegation when approved.

5. TOOL ECOSYSTEM
Develop atomic, deterministic tools for:
- filesystem & local PC operations
- code execution & validation
- web research & data retrieval
- remote compute delegation (pod spinning, task submission, result retrieval)
- media generation wrappers (image/video/audio via remote services)
- system inspection & maintenance
- sensitive data handling (local encryption, access control)

Tools must remain simple, logged, and manager-approved.

6. VERIFIED OUTPUT & STRICT CONTROL
All outputs must be verified by tester_agent or equivalent.
Execution model:
Goal → Manager planning → Execution → Validation → Repair if needed → Confirmed result
No unverified success allowed. Manager enforces repair limits and vetoes fabricated termination.

7. AUTONOMOUS TASK DECOMPOSITION & WORKFLOW EXECUTION
Break complex goals into structured or hierarchical steps.
Execute multi-step workflows automatically, including:
- creative pipelines (script → storyboard → generation → assembly → edit)
- development cycles (code gen → test → fix → deploy)
- personal maintenance (PC health checks, backups, updates)

8. PERSISTENT SUB-SYSTEMS
Support long-lived, goal-specific sub-systems registered in memory.
Example: Movie Production Studio
- Accepts script/concept as input
- Spawns dedicated agents and tools
- Delegates media generation remotely
- Produces final rendered movie file locally
- Maintains state across sessions

9. PERSISTENT SYSTEM MEMORY & KNOWLEDGE
Maintain structured awareness of:
- tools, agents, sub-systems
- projects & execution history
- repair patterns & learned fixes
- sensitive data indexes (local only)

10. CONTEXTUAL LEARNING & SELF-IMPROVEMENT
Store and learn from:
- past executions
- successful/failed repairs
- recurring issues
- workflow outcomes
Evolve toward recursive self-modification (manager-approved changes to code, tools, agents).

11. PROJECT & SYSTEM AWARENESS
Understand local project structures, dependencies, and state.
Self-inspect: list capabilities, analyze logs, explain architecture.

12. SYSTEM MAINTENANCE & HEALTH
Support:
- automated PC health checks & optimization
- regression testing
- failure detection
- architecture validation

13. AI-ASSISTED DEVELOPMENT & CREATION
Assist in:
- writing code, apps, websites, games
- generating content (articles, scripts, media)
- debugging & repairing
- creating new agents/tools/sub-systems

14. REVENUE & PERSONAL ASSISTANCE
Support money-making activities through:
- app/website/game prototypes
- content creation
- market research
- automation of income-generating tasks
No direct financial transactions without explicit human approval.

15. SAFE DELEGATION & PRIVACY
- Sensitive data remains local
- Remote compute calls are encrypted, audited, and reversible
- Manager approves every delegation
- No cloud decision-making or storage of core state

16. MODULAR & EXTENSIBLE DESIGN
Components:
- Manager (core orchestrator)
- Agents
- Tools
- Sub-systems
- Memory & logging
- Remote delegation layer

17. TRANSPARENCY & OBSERVABILITY
Expose:
- reasoning traces
- execution logs
- repair history
- sub-system state
- delegation audits

18. CONTROLLED AUTONOMY
Operate within E:\AI_Lab (expandable with approval).
Human supervision and veto always possible.
