## CORE RULES

1. SMALL, ISOLATED CHANGES ONLY

* Never request large refactors
* One logical change per task
* Each step must be testable

---

2. NEVER ASSUME SYSTEM BEHAVIOR

If unsure about:

* data structures
* execution flow
* dependencies

→ FIRST run an AUDIT task

---

3. DO NOT LET WINDSURF “BE CREATIVE”

Windsurf must:

* follow instructions EXACTLY
* NOT redesign architecture
* NOT add extra features

If it does → reject and correct

---

4. ALWAYS DEFINE

* goal
* files to modify
* exact functions
* exact behavior
* what NOT to do

---

5. NO SILENT CHANGES

Every change must be:

* explicit
* justified
* reported

---

6. ALWAYS REQUIRE A REPORT

Each task MUST return:

* what was changed
* where (file + location)
* why
* test results

---

## TESTING DISCIPLINE (MANDATORY)

Testing tasks MUST produce real execution evidence.

Windsurf MUST:

- run actual code
- capture real outputs
- expose intermediate states

Windsurf MUST NOT:

- simulate outputs
- infer behavior
- assume correctness

All test reports MUST include:

- raw outputs
- layer-by-layer trace

If a test cannot produce real outputs:

→ STOP and report inability

No test may be completed without evidence.
