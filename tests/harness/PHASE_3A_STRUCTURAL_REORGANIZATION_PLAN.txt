# 1. REORGANIZATION PHILOSOPHY

### CORE PRINCIPLE: SEMANTIC GOVERNANCE BEFORE STRUCTURAL GOVERNANCE

The validation ecosystem is now semantically governed. Phase 2B successfully added metadata headers to all 73 validation test files. Each test now declares CATEGORY, AUTHORITY_LAYER, VALIDATES, ENTRYPOINT, DIRECT_INTERNAL_CALLS, MONKEYPATCH_USAGE, MOCKING_POLICY, TEST_INTENT, ARCHITECTURAL_SCOPE.

**Metadata is authoritative.** File location is NOT authoritative. Metadata CATEGORY field determines the correct folder.

### STRUCTURE FOLLOWS DECLARED AUTHORITY

The target folder structure is designed to align filesystem topology with declared authority boundaries. Folder placement is determined by CATEGORY, AUTHORITY_LAYER, and TEST_INTENT fields. File location is secondary. Metadata is primary.

### RELOCATION MUST PRESERVE BEHAVIOR

File movement must NOT break imports, pytest discovery, fixture resolution, test execution, or test behavior. File movement MUST preserve import paths (update if needed), fixture resolution (update if needed), pytest discovery (update if needed), and metadata headers.

### MIGRATION MUST PRESERVE HISTORICAL KNOWLEDGE

Regression tests preserve architectural lessons. Stabilization tests preserve convergence history. File movement must NOT delete regression or stabilization tests, alter historical context, or alter metadata headers.

### REGRESSION PRESERVATION OVERRIDES AESTHETIC CLEANUP

Regression tests may use ugly patterns to accurately reproduce historical bugs. File movement must NOT clean up regression test code, refactor regression test patterns, or alter historical reproductions. Regression value overrides aesthetic purity.

### MOVEMENT IS MECHANICAL, NOT SEMANTIC

File movement is a mechanical operation: read metadata CATEGORY, determine target folder from CATEGORY, move file to target folder, update imports if needed, update pytest configuration if needed. File movement is NOT semantic reclassification (already done in Phase 2B), metadata modification (already done in Phase 2B), or test modification (forbidden in Phase 3).

### FOLDERS ARE CONVERGENCE MECHANISMS, NOT TRUTH

Folders exist to align filesystem with declared authority, enable category-based discovery, enable category-based enforcement, and improve navigability. Folders do NOT define test category (metadata does), define test authority (metadata does), or define test intent (metadata does). Metadata defines truth. Structure expresses truth.

# 8. ROLLBACK STRATEGY

### ROLLBACK TRIGGER

Rollback is triggered by:
1. Syntax error (python -m py_compile fails)
2. Import error (import fails)
3. Pytest discovery failure (pytest --collect-only fails)
4. Fixture resolution error (fixture cannot be resolved)
5. Metadata header modification (metadata header altered)
6. Test execution failure (test that passed before move fails after move)
7. Test behavior change (test behavior changes after move)
8. Silent discovery drift (test count changes without error)

### ROLLBACK SCOPE

Rollback scope is per migration phase:
* Phase 3B rollback: Rollback all files moved in Phase 3B only
* Phase 3C rollback: Rollback all files moved in Phase 3C only
* Phase 3D rollback: Rollback all files moved in Phase 3D only
* Phase 3E rollback: Rollback all files moved in Phase 3E only
* Phase 3F rollback: Rollback all files moved in Phase 3F only

Rollback does NOT cascade. Each phase is independent.

### ROLLBACK ORDER

Rollback order is reverse of migration order for each phase.

### VALIDATION REQUIREMENTS

After rollback, validate:
1. Syntax validation on all rolled back files
2. Import validation
3. Pytest discovery validation on all folders
4. Test execution validation
5. Metadata header validation
6. File count validation

Rollback is only complete when all files are restored to original locations, all syntax checks pass, all imports work, all pytest discovery works, all tests execute successfully, and all metadata headers are preserved.

### ROLLBACK BEFORE CORRUPTION

Rollback principle: Rollback before corruption. Do NOT continue migration after failure. Do NOT attempt partial fixes mid-migration. Do NOT leave repository in inconsistent state. Rollback immediately on any failure. Investigate failure after rollback. Fix root cause before retry.

### ROLLBACK BEFORE AMBIGUITY

Rollback principle: Rollback before ambiguity. Do NOT continue if category classification is unclear. Do NOT continue if entry point usage is ambiguous. Do NOT continue if direct call legitimacy is uncertain. Rollback and review before retry.
