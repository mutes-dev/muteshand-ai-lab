# 1. CURRENT AUTHORITATIVE VALIDATION MODEL

---

## AUTHORITY LAYER DEFINITIONS

### HARNESS = EXTERNAL OBSERVABLE TRUTH

**Purpose:** Validate what the system RETURNS to external callers

**Authority:**
- Defines external API contract
- Enforces output schema
- Guarantees determinism
- Prevents regression

**Scope:**
- Tests public API surface
- Validates externally observable behavior
- No knowledge of internal implementation
- Contract enforcement only

**Entry Point:** `execute_from_input(user_input: str)`

**Contract Type:** Layered (nested status/result structure)

**Location:** `tests/harness/`

---

### INTERNAL = RUNTIME BEHAVIORAL TRUTH

**Purpose:** Validate how the system BEHAVES internally

**Authority:**
- Defines retry logic behavior
- Validates state transitions
- Tests failure modes
- Controls execution path (mocking permitted)

**Scope:**
- Tests internal orchestrator logic
- Validates behavioral correctness
- Uses controlled mocking (monkeypatch)
- Direct workflow construction

**Entry Point:** `run_workflow(workflow: dict)`

**Contract Type:** Flat (direct status/result structure)

**Location:** `tests/internal/` (formerly `system/tests/`)

---

### CORE PIPELINE = EXECUTION TRUTH

**Purpose:** Validate core execution pipeline correctness

**Authority:**
- Defines execution truth
- Enforces deterministic behavior
- Validates structural contracts
- Guarantees single-step execution

**Scope:**
- Tests core pipeline components
- Validates tool execution
- Tests validation gates
- Validates parser/resolver behavior

**Entry Point:** `system_entry(tool_call: str)`

**Contract Type:** Flat (direct status/result structure)

**Location:** `tests/validation/` (for execution validation)

---

# 3. CONTRACT LAYER OWNERSHIP

---

## FLAT CONTRACT OWNERSHIP

**Owned By:**
- Internal Runtime Tests (INTERNAL_RUNTIME)
- Core Pipeline Tests (VALIDATION)
- Governance Tests (GOVERNANCE) - for governance-specific contracts
- Lifecycle Tests (LIFECYCLE) - for lifecycle-specific contracts
- Projection Tests (PROJECTION) - for projection-specific contracts
- Observability Tests (OBSERVABILITY) - for observability-specific contracts

**Contract Structure:**
```python
{
    "status": "success",
    "result": <value>
}

# OR

{
    "status": "failure",
    "reason": <string>
}
```

**Ownership Rules:**
- Internal tests validate flat contract
- Core pipeline produces flat contract
- Unit-level tests validate component-specific flat contracts

---

## LAYERED CONTRACT OWNERSHIP

**Owned By:**
- Harness Tests (HARNESS_CONTRACT) — EXCLUSIVE

**Contract Structure:**
```python
{
    "status": "success",
    "result": {
        "status": "success",
        "result": <value>
    }
}

# OR

{
    "status": "failure",
    "reason": <string>
}
```

**Ownership Rules:**
- Harness tests validate layered contract EXCLUSIVELY
- Internal tests NEVER validate layered contract
- Layered contract is external transformation applied by execute_from_input

---

## EXTERNAL CONTRACT OWNERSHIP

**Owned By:**
- Harness Tests (HARNESS_CONTRACT)
- Integration Tests (INTEGRATION) — for end-to-end validation

**Ownership Rules:**
- External contract is layered contract structure
- Only harness and integration tests validate external contract
- Internal tests do not validate external contract

---

## INTERNAL RUNTIME OWNERSHIP

**Owned By:**
- Internal Runtime Tests (INTERNAL_RUNTIME)
- Governance Tests (GOVERNANCE)
- Lifecycle Tests (LIFECYCLE)
- Projection Tests (PROJECTION)

**Ownership Rules:**
- Internal runtime tests validate internal behavior
- Internal runtime tests use flat contract
- Internal runtime tests may use monkeypatching for behavior control
