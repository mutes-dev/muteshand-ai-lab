# DATA FLOW (SOURCE OF TRUTH)

CORE PIPELINE FLOW:

User Input (string)
→ Planner (structure only)
→ Parser (numeric + quoted string extraction)
→ Resolver (positional mapping)
→ Validation (FAIL-FAST — blocks invalid plans)
→ Execution (runtime — only valid plans, single-step)
→ Result

EXECUTION BOUNDARY:

system_entry(input) → routes to Core Pipeline → returns Normalized Result

NOTE: system_entry is the execution boundary of the deterministic core pipeline.
It is NOT part of the core deterministic pipeline.
It is NOT the orchestrator layer itself.

Execution → Result → Orchestrator Layer:
- Validator (advisory)
- Governance (determines retry, continuation, failure, and final output decisions)

# 🔧 INPUT NORMALIZATION (PLANNER PRE-PROCESSING)

Planner includes deterministic normalization:

system/planner/deterministic_planner.py → normalize_input_text()

---

## PURPOSE

Convert implicit chaining into explicit form.

Example:

add 2 and 3 then multiply by 4
→ add 2 and 3 then multiply the result by 4

---

## IMPLEMENTATION MODEL

* clause-based processing
* strict token structure
* deterministic substitution

---

## 🔒 CONSTRAINTS

* Regex allowed ONLY in semantic mapping layer
* Regex FORBIDDEN in: normalization, parsing, argument resolver
* NO interpretation
* NO NLP

---

## RULE

This is NOT parsing.

This is deterministic preprocessing ONLY.
