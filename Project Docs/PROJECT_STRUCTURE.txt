# DATA FLOW (INTENDED — SOURCE OF TRUTH)

User Input
→ Planner (structure only)
→ Parser (tokens)
→ Argument Resolver (arguments)
→ Chain Resolver (dependency injection)
→ Validation (structure check)
→ Execution (runtime)
→ Result

# ⚠️ RUNTIME CHAIN RESOLUTION (APPROVED DESIGN)

Chain Resolver operates inside execution loop.

Reason:

- Requires actual execution results
- Cannot run before execution
- Ensures correct dependency injection timing

Status:

✅ Architecturally correct

## ⚠️ EXECUTION LAYER NOTE (IMPORTANT)

Execution logic is embedded inside:

projects/manager/manager.py

## CURRENT RESPONSIBILITIES

Manager currently handles:

# 🔧 INPUT NORMALIZATION (PLANNER PRE-PROCESSING)

Planner includes deterministic normalization:

core/planner.py → normalize_input_text()

---

## PURPOSE

Convert implicit chaining into explicit form.

Example:

add 2 and 3 then multiply by 4
→ add 2 and 3 then multiply the result by 4

---

## IMPLEMENTATION MODEL

* clause-based processing
* strict token structure
* deterministic substitution

---

## 🔒 CONSTRAINTS

* Regex allowed ONLY in semantic mapping layer
* Regex FORBIDDEN in: normalization, parsing, argument resolver
* NO interpretation
* NO NLP

---

## RULE

This is NOT parsing.

This is deterministic preprocessing ONLY.

---

# SEMANTIC MAPPING LAYER

## LOCATION

core/planner.py → SEMANTIC_PATTERNS

## PURPOSE

Deterministic routing from known phrases to tool names.

## CONSTRAINTS

- Regex allowed ONLY here
- Explicit patterns only
- One pattern → one tool
- No overlap
- Tool existence verified before routing
- Arguments NOT extracted
