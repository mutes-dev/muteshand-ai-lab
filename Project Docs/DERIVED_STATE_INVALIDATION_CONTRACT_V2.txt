## PURPOSE

Defines invalidation behavior for derived execution artifacts.

This contract governs:

* tool_call lifecycle
* compiled execution artifacts
* cached execution state
* downstream recomputation
* semantic mutation propagation

This contract does NOT own lifecycle truth.
This contract does NOT own execution truth.
This contract does NOT authorize retry, replay, or recovery by itself.
Derived state invalidation is downstream of authoritative mutation, lifecycle, and execution identity decisions.

---

## CORE PRINCIPLE

Derived execution artifacts are NOT canonical truth.

Derived artifacts MUST be invalidated when upstream semantic meaning changes.

Derived state invalidation is an advisory downstream mechanism.
Authoritative mutation, lifecycle, and execution identity decisions trigger invalidation.

---

# 1. DERIVED STATE TYPES

Derived execution artifacts MAY include:

* tool_call
* compiled execution plans
* cached validator outputs
* cached execution context
* cached dependency evaluations
* projection snapshots
* retry metadata

---

# 2. tool_call SEMANTICS

tool_call is:

* derived execution state
* compiled execution artifact
* non-canonical

tool_call MUST NOT be treated as immutable semantic truth.

---

# 3. INVALIDATION TRIGGERS

Derived artifacts MUST invalidate when:

* semantic mutation occurs (governed by MUTATION_LEGALITY_AND_RUNTIME_ISOLATION_CONTRACT_V2)
* dependency meaning changes
* execution strategy changes
* retry regeneration occurs (governed by EXECUTION_IDENTITY_AND_REPLAY_CONTRACT_V2)
* plan mutation occurs (governed by WORKFLOW_STUDIO_AND_OPERATIONAL_MUTATION_CONTRACT_V2)

---

# 4. SEMANTIC EXPECTATION MUTATION

Semantic expectation mutation MAY invalidate:

* semantic drift baselines
* semantic comparison artifacts
* semantic observability caches

Semantic expectation invalidation semantics are governed separately by:
SEMANTIC_EXPECTATION_MODEL_CONTRACT_V2

---

# 5. SEMANTIC MUTATION RULE

Semantic mutation MUST invalidate:

* tool_call
* compiled execution artifacts
* dependency-derived execution state

This prevents stale execution behavior.

Invalidation decisions are downstream of:
- mutation legality validation
- lifecycle authority
- execution identity rules

---

# 6. DOWNSTREAM INVALIDATION

Upstream semantic mutation MAY invalidate downstream nodes.

Downstream recomputation MUST occur when:

* dependency semantics change
* execution assumptions become stale

---

# 7. COMPLETED NODE RECOMPUTATION

Completed downstream nodes remain immutable under current architecture.

COMPLETED is an immutable terminal state.
CANCELLED is an immutable terminal state.

Historical recomputation of COMPLETED nodes is NOT currently supported.

If future historical recomputation is introduced:

* downstream invalidation semantics MUST expand formally

---

# 8. RETRY REGENERATION

Retry MAY regenerate:

* tool_call
* prompts
* execution inputs
* derived execution plans

Retry regeneration is governance-controlled.
Retry regeneration is governed by EXECUTION_IDENTITY_AND_REPLAY_CONTRACT_V2.

Derived state invalidation does NOT authorize retry by itself.

---

# 9. CACHE INVALIDATION

Invalidated derived artifacts MUST NOT remain executable.

Stale derived execution state MUST be regenerated before execution resumes.

---

# 10. PROJECTION INVALIDATION RELATIONSHIP

Derived-state invalidation MAY trigger:

* projection invalidation
* projection refresh
* projection regeneration

Projection invalidation semantics remain governed by:
PROJECTION_CONTINUITY_CONTRACT_V2

Projection is non-authoritative per CANONICAL_PROJECTION_MODEL_V2.
Derived-state invalidation MUST NOT treat projection as authoritative truth.

---

# FINAL PRINCIPLE

Derived execution artifacts are mutable derived state.

Semantic truth changes MUST invalidate stale execution artifacts deterministically.

Derived state invalidation is downstream of:
- lifecycle authority
- execution identity authority
- mutation legality authority

Derived state invalidation does NOT own any of the above authorities.
