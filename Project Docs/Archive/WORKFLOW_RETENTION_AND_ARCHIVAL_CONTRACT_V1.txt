# AI LAB — WORKFLOW RETENTION AND ARCHIVAL CONTRACT V1

## PURPOSE

Formalize:

* workflow retention model
* Task Hub ownership model
* History/Archive ownership model
* recoverable workflow visibility
* terminal workflow retention
* lifecycle state vs retention state separation

This contract governs:
workflow retention, archival semantics, and historical workflow management architecture.

NOT:

* lifecycle authority ownership
* execution identity semantics
* runtime coordination
* projection continuity mechanics
* Workflow Studio operational behavior
* Task Hub implementation mechanics

---

## CORE PRINCIPLE

Lifecycle State
≠
Retention State

Examples:

* COMPLETED
* FAILED
* CANCELLED
* ACTIVE

are lifecycle concepts.

* Retained
* Archived
* Dismissed
* Deleted

are retention concepts.

These domains are independent.

---

## 1. TASK HUB CONTRACT

Task Hub represents:

Recoverable / Actionable Work

Include:

* ACTIVE
* PAUSED
* PENDING_RECOVERY
* recoverable FAILED
* QUEUED_REPLAN_REQUIRED (actionable replan item)

Exclude:

* COMPLETED
* CANCELLED
* archived workflows
* historical workflows
* QUEUED_LIVE_PLANNING (if shown separately from actionable runtime)

Task Hub MUST distinguish:

* recoverable runtime
* live planning
* replan-required planning request

QUEUED_REPLAN_REQUIRED in Task Hub:

* is an actionable planning-request retention item
* is NOT historical terminal work
* should expose operator action: Resume Planning / Replan
* must not be shown as live/restorable execution

Archived or dismissed planning requests:

* should move out of Task Hub
* belong in History/Archive

Task Hub is NOT:

* historical storage
* archival index
* inspection-only history

Task Hub ownership is:
recoverable work management.

---

## 2. HISTORY / ARCHIVE CONTRACT

History represents:

Previously existing workflows.

History is:

* observability-oriented
* inspection-oriented
* non-actionable

History is NOT:

* recoverability-oriented
* actionable
* lifecycle-authoritative

Examples:

* COMPLETED
* CANCELLED
* archived FAILED
* historical workflows

History MAY include:

* terminal workflows
* dismissed workflows
* previously active workflows

History MUST NOT:

* suggest retry legality
* imply recoverability
* override lifecycle authority

---

## 3. FAILED RECOVERABILITY MODEL

Current architectural assumption:

FAILED = Recoverable Terminal

Retry remains legal.

Retry creates:
new execution lineage.

FAILED workflows remain actionable unless explicitly archived or dismissed.

Future expansion MAY introduce:

* FAILED_IRRECOVERABLE
* or equivalent recoverability metadata

Current architecture does NOT require this distinction.

Recoverability semantics remain governed by:
LIFECYCLE_AUTHORITY_CONTRACT_V1
EXECUTION_IDENTITY_AND_REPLAY_CONTRACT_V1

---

## 4. RETENTION ACTIONS

Retention actions are future concepts that do NOT alter lifecycle truth.

### Retain

Preserve workflow visibility in active surfaces.

Does NOT change lifecycle state.

### Archive

Move workflow to historical visibility only.

Does NOT change lifecycle state.

### Dismiss

Remove workflow from active surfaces without deletion.

Does NOT change lifecycle state.

### Delete

Permanently remove workflow record.

Does NOT retroactively alter lifecycle truth.

Explicitly define:

Retention actions do NOT alter lifecycle truth.

Lifecycle truth is immutable.

Retention state is a separate classification layer.

---

## 5. TERMINAL WORKFLOW MANAGEMENT

Terminal workflows MAY eventually support:

* retention classification
* archival transition
* dismissal from active surfaces
* deletion

Terminal workflow management:

* is retention-layer behavior
* is NOT lifecycle-layer behavior
* does NOT modify lifecycle state

Lifecycle authority remains unchanged.

---

## 6. OWNERSHIP MODEL

| Layer | Ownership |
|-------|-----------|
| Workflow Studio | operational interaction |
| Task Hub | recoverable work management |
| History / Archive | historical visibility |
| Lifecycle Authority | lifecycle truth |
| Retention Layer | retention classification |

Each layer is:

* architecturally separate
* MUST NOT be conflated
* MUST NOT substitute for one another

---

## 7. PROHIBITED PATTERNS

The following are PROHIBITED:

* retention actions altering lifecycle truth
* archive mutating lifecycle state
* Task Hub becoming historical archive
* lifecycle state inferred from retention state
* retention state becoming lifecycle authority
* historical visibility implying recoverability
* archival transition reversing terminalization

---

## 8. PROJECTION RELATIONSHIP

Projection visibility MAY include:

* retention metadata
* archival metadata
* recoverability classification

Projection visibility remains non-authoritative.

Retention metadata in projections:

* is read-model advisory only
* does NOT define lifecycle truth
* does NOT authorize retention actions

---

## 9. FUTURE DIRECTION

Future workflow management epic MAY include:

* History UI
* Archive UI
* Retention controls
* Recoverability visibility
* Lifecycle management UX
* Dismiss/archive/delete operations

Future workflow management MUST preserve:

* lifecycle truth independence
* retention-state independence
* retry lineage semantics
* authority hierarchy

Lifecycle State
≠
Retention State

Task Hub = actionable work

History = historical work

Lifecycle Authority owns lifecycle truth.
