prevent operator entrapment in doomed execution.

- authority hierarchy

- convergence guarantees

Cancellation does NOT bypass:
- lifecycle authority

---

## 2. Terminal State Classification

### Immutable Terminal

States:
- COMPLETED
- CANCELLED

Immutable terminal states do NOT imply archival state.

Lifecycle state and retention state are independent.

Cancellation does not imply archival.

Terminalization does not imply retention.

Retention actions, if introduced, do NOT alter lifecycle truth.

Immutable terminal states:
- do NOT support retry
- do NOT support continuation
- do NOT support structural mutation
- MAY support observability and inspection

### Recoverable Terminal

State:
- FAILED

Recoverable terminal state MAY support:
- retry (creates NEW execution lineage)
- reconciliation
- adaptive continuation
- future branch healing

FAILED may support authorized recovery/retry/re-execution through current contracts.

### Recoverable Non-Terminal / Wait State

State:
- BLOCKED

BLOCKED may support:
- resolution
- retry
- replan

BLOCKED is a recoverable non-terminal/wait state only.

## 3. Cancellation Authority

Cancellation belongs to:
workflow-scoped operational control authority.

Cancellation is REQUESTED through:
operator interaction surface / user/backend control path.

Cancellation is VALIDATED under:
USER_CONTROL_CONTRACT_V3.

Cancellation is DECIDED / PERMITTED by:
Governance where needed.

Cancellation is COMMITTED by:
Lifecycle Authority.

Cancellation does NOT bypass:
- lifecycle authority
- execution identity rules
- mutation legality
- convergence guarantees

Cancellation is:
authority-coordinated termination,
NOT authority-bypassing termination.

---

## 4. Cancellation Effects

Intended effects of cancellation:
- active execution invalidation
- downstream execution prevention
- runtime coordination cleanup
- projection synchronization
- operator-visible terminalization

Cancellation creates:
terminalized execution lineage.

CANCELLED creates immutable terminal CANCELLED lineage.

CANCELLED does NOT support:
- retry
- continuation
- recovery mutation
- structural mutation
- re-execution

Cancellation does NOT create:
- stale execution continuation
- unauthorized mutation windows
- projection-owned termination
- frontend lifecycle synthesis
- archival state
- retention classification

---

## 5. Safe Terminalization

Terminalization MUST remain:
authority-first.

Synchronization/projection failures MUST NOT prevent:
terminal lifecycle convergence.

Lifecycle Authority commits terminalization BEFORE:
downstream synchronization per ORCHESTRATION_AND_EXECUTION_SEQUENCE_CONTRACT_V2.

Cancellation sequencing:
1. Cancellation requested through user/backend control path
2. Backend validates under USER_CONTROL_CONTRACT_V3
3. Governance decides/permitts where needed
4. Lifecycle Authority commits CANCELLED
5. Runtime Registry coordinates worker invalidation/shutdown (does not block Lifecycle Authority)
6. Persistence synchronizes downstream
7. Projections refresh
8. Stream transport emits final synchronization
9. Frontend converges

Align sequencing with ORCHESTRATION_AND_EXECUTION_SEQUENCE_CONTRACT_V2 and SYSTEM_CONVERGENCE_AND_RECOVERY_CONTRACT_V2.

Projection sync failure does NOT block lifecycle terminalization.

Stream sync failure does NOT block lifecycle terminalization.
