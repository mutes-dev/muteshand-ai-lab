**Goal:** Exactly one layer owns lifecycle truth. Transitions are deterministic. No authority fragmentation.

**Status:** ALIGNED — Implementation correctly binds lifecycle authority to runtime registry per LIFECYCLE_AND_PROJECTION_AUTHORITY_CONTRACT_V1 §SINGLE LIFECYCLE AUTHORITY RULE. `_workflow_state_registry` is the current concrete implementation of the Lifecycle Authority architectural role.

**Reference Documents:**
- LIFECYCLE_AUTHORITY_CONTRACT_V1.txt
- LIFECYCLE_AND_PROJECTION_AUTHORITY_CONTRACT_V1.txt

**Checklist:**

- [x] Exactly ONE layer owns lifecycle truth — `_workflow_state_registry` correctly implements sole lifecycle authority per contract
- [x] No other layer mirrors, caches, or duplicates lifecycle state as authority — persistence correctly injects authoritative lifecycle before exposing (inject_authoritative_lifecycle_into_workflow)
- [x] Lifecycle transitions are deterministic (no ambiguous paths) — FSM defined in `workflow_control.py`
- [~] Lifecycle state changes are atomic where required — `threading.RLock` used; atomicity partially verified
- [x] No projection layer synthesizes lifecycle truth — ProjectionManager correctly derives from runtime authority, emits downward-only, does NOT synthesize
- [x] No stream/registry overwrites lifecycle state — Stream registry correctly caches projection state, consumes from authority via _get_workflow_state()
- [~] Lifecycle authority is independent from synchronization success — partially; persistence failure is non-fatal
- [~] Lifecycle commits before downstream synchronization — partially implemented
- [x] Authority fragmentation is impossible (no split ownership) — `core/` provides deterministic utilities; `system/` owns execution authority. No split lifecycle ownership.

**Done When:**
- Singular lifecycle authority confirmed
- No layer can override lifecycle state

**Drift Detection:**
- Multiple components claim lifecycle ownership
