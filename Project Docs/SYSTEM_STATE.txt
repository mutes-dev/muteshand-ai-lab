### EXECUTION BOUNDARY

```
system_entry(input) → parse → resolve → validate → execute → Normalized Result
```

**Definition:**
- system_entry IS the core execution layer and the ONLY execution boundary
- It is the ONLY valid gateway for tool execution
- It accepts ONLY tool_call strings
- It performs NO planning, NO normalization, NO input correction
- Runtime does NOT generate or modify execution input
- tool_call is sole execution input (explicit, non-null)
- No purpose-based execution allowed

```
Orchestrator Layer (runtime) → system_entry → Core Pipeline → Result
                                    ↑
                            Validation (advisory)
                            Governance (decision authority)
```

**Orchestrator Responsibilities:**
- Workflow execution control
- Agent coordination
- Step management
- Governance-controlled retry
- Context injection (last_result)

**Orchestrator Constraints:**
- MUST route ALL execution through system_entry
- MUST NOT access parser/resolver/validation/execution directly
- MUST NOT modify execution data
- MUST NOT introduce randomness into execution

## RETRY REALITY

Retry may include instruction injection.

Example:

```
IMPORTANT: Return ONLY the number.
```

However:

- execution behavior is unchanged
- tool selection is unchanged
- execution_result remains identical

Conclusion:

Retry does NOT correct logical failures.

Agent re-executes using the same (modified text) input. No input adaptation based on the root cause of the failure exists.

---

## MEMORY CONTROLLER

Memory controller exists at orchestrator level.

Capabilities:
- store context (`set_last_result`, `append_step_history`)
- retrieve prior information (`get_last_result`, `get_context`)

LIMITATION:

Memory is advisory only.

Memory does NOT:
- influence `execution_result`
- influence governance decisions
- enable correction

Memory is used for step chaining (passing `last_result` between steps). It does not evaluate correctness or drive retry logic.

---

## CRITICAL LIMITATION — NO CORRECTION MECHANISM

The system currently lacks a correction mechanism.

- `execution_result` may be successful but incorrect
- validator detects issues but signals are not used by governance
- retry re-executes same input (with optional text injection)
- no input adaptation exists

Result:

System may complete with incorrect outputs.

This is a known, documented limitation. It does not represent a bug in the current architecture — signals are observational by design. Correction requires a future phase.
