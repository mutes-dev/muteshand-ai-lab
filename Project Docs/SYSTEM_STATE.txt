## 2. EXECUTION MODEL

### CORE PIPELINE (DETERMINISTIC, SINGLE-STEP)

```
Planner → Parser → Resolver → Validation → Execution
```

**Constraints:**
- NO multi-step logic
- NO chaining
- NO LLM-driven retries
- Deterministic execution only

### EXECUTION BOUNDARY

```
system_entry(input) → routes to Core Pipeline → returns Normalized Result
```

**Definition:**
- system_entry is the execution boundary between orchestrator and core pipeline
- It is NOT part of the core deterministic pipeline
- It is NOT the orchestrator layer itself
- It is the ONLY valid gateway for tool execution

### ORCHESTRATOR FLOW

```
Orchestrator Layer (runtime) → system_entry → Core Pipeline → Result
                                    ↑
                            Validation (advisory)
                            Governance (decision authority)
```

**Orchestrator Responsibilities:**
- Workflow execution control
- Agent coordination
- Step management
- Governance-controlled retry
- Context injection (last_result)

**Orchestrator Constraints:**
- MUST route ALL execution through system_entry
- MUST NOT access parser/resolver/validation/execution directly
- MUST NOT modify execution data
- MUST NOT introduce randomness into execution
