## 1.1 Deterministic Authority Model

- execution_result is sole runtime truth
- governance is sole decision maker
- lifecycle authority owns lifecycle transitions
- signals are advisory only and cannot override execution_result
- Verified by: AUTHORITY_MODEL.txt, CONTROL_MODEL.txt, ARCHITECTURE_LAW.txt

## 1.2 Governance Isolation

- Governance layer is isolated from execution layer
- Governance owns retry, completion, failure, escalation
- Governance does not execute tools, use LLM, or modify execution_result
- Verified by: GOVERNANCE_CONTRACT.txt, CONTROL_MODEL.txt

## 1.3 Replay/Recovery Legality

- Recovery restores authoritative runtime state WITHOUT creating new execution identity
- Replay creates NEW execution identity
- Retry generates new execution identity
- Reconstruction and replay are semantically distinct
- Verified by: EXECUTION_IDENTITY_AND_REPLAY_CONTRACT_V1.txt

## 1.4 Mutation Legality

- ACTIVE execution is immutable
- Direct semantic mutation during ACTIVE execution is prohibited
- Mutation requests during ACTIVE execution MUST be rejected or deferred
- Operational mutations are lightweight and governed by WORKFLOW_STUDIO contract
- Verified by: MUTATION_LEGALITY_AND_RUNTIME_ISOLATION_CONTRACT_V1.txt, WORKFLOW_STUDIO_AND_OPERATIONAL_MUTATION_CONTRACT_V1.txt

## 1.5 Projection Non-Authority

- Projections are derived representations, NOT authority
- Stream/UI projections MUST reflect authoritative lifecycle state
- Projections MUST NOT synthesize lifecycle truth
- Projection divergence is legal during streaming/retry/mutation/pause/resume
- Permanent divergence is prohibited
- Verified by: PROJECTION_CONTINUITY_CONTRACT_V1

## 1.6 Semantic Advisory Posture

- Semantic systems are advisory only
- Semantic systems MUST NOT override execution_result
- Semantic systems MUST NOT claim lifecycle authority
- Semantic systems MUST NOT trigger retry independently
- Semantic signals trigger escalation only, never authority transfer
- Verified by: SEMANTIC_EXPECTATION_MODEL_CONTRACT_V1.txt, AUTHORITY_MODEL.txt, INTELLIGENCE_LAYER_BOUNDARY_RECONCILIATION_AUDIT_V1.txt

## 1.7 Centralized Orchestration Posture

- Orchestrator is centralized coordination authority
- Sequencing ownership is centralized
- Routing ownership is centralized
- No distributed orchestration topology exists or is planned for AG1
- Verified by: ORCHESTRATOR_CONTRACT_V2.txt, ARCHITECTURE_LAW.txt

## 1.8 AG1 Containment Architecture

- AG1 agents are bounded semantic infrastructure
- AG1 agents are NOT runtime authority infrastructure
- AG1 agents are stateless, advisory-only, non-authoritative
- AG1 agents do NOT own orchestration, lifecycle, execution identity, or mutation authority
- Verified by: AGENT_GOVERNANCE_CONTRACT_V1.txt, AGENT_ARCHITECTURE_AUTHORITY_VERIFICATION_V1.txt, SA_AGENT_ARCHITECTURE_FINALIZATION_V1.txt

## 1.9 Recovery Survivability

- Recovery converges to authoritative lifecycle state
- Recovery does NOT replay execution
- Stale-state quarantine prevents stale persistence from overwriting authority
- Verified by: SYSTEM_CONVERGENCE_AND_RECOVERY_CONTRACT_V1

## 1.10 Retry Lineage Semantics

- Retry generates new execution identity
- Retry is a NEW execution attempt, NOT a continuation
- Failed execution recovery uses retry semantics
- Intentional cancellation uses terminalization semantics
- Verified by: EXECUTION_IDENTITY_AND_REPLAY_CONTRACT_V1.txt

# 7. ACCEPTED LIMITATIONS

The following limitations are explicitly reconciled and accepted.
They are NOT defects.
They are NOT architecture failures.
They are NOT implementation drift.
They are intentional operational constraints.

## 7.1 Polling Transport Fallback

- **Status:** ACCEPTED
- **Why accepted:** Transport-agnostic architecture permits polling as legal fallback. Websocket is refinement, not requirement.
- **Operational impact:** Slightly reduced projection freshness under fallback conditions
- **Escalation threshold:** If polling becomes an observed blocker for AG1 observability, operator trust, performance, or workflow scale. Polling remaining the sole current transport is accepted and not itself a defect.
- **Note:** ISSUE-068A and SA review confirmed push transport is optional optimization, not current correctness requirement.

## 7.2 Mirror Durability Model

- **Status:** ACCEPTED
- **Why accepted:** Mirror durability provides adequate persistence for current operational needs
- **Operational impact:** Recovery depends on mirror state; some edge cases may require manual intervention
- **Escalation threshold:** If mirror durability proves insufficient for production SLA requirements

## 7.3 Planner Ambiguity

- **Status:** ACCEPTED
- **Why accepted:** Planner is advisory-only semantic system; ambiguity does not affect runtime authority
- **Operational impact:** Planner may produce suboptimal recommendations in edge cases
- **Escalation threshold:** If planner ambiguity causes operational confusion or operator distrust

## 7.4 Planner Non-Determinism

- **Status:** ACCEPTED
- **Why accepted:** LLM-assisted planner is intentionally non-deterministic; execution layer is deterministic; separation is correct
- **Operational impact:** Same input may produce different planner output on different runs
- **Escalation threshold:** If non-determinism affects execution correctness (would indicate architecture violation, not planner limitation)

## 7.5 Single-Agent Topology

- **Status:** ACCEPTED
- **Why accepted:** Multi-agent coordination is outside AG1 scope per AGENT_GOVERNANCE_CONTRACT_V1.txt
- **Operational impact:** System operates with single bounded agent or domain-specialized agents without coordination
- **Escalation threshold:** If operational requirements demand multi-agent coordination (requires SA escalation and architecture review)

## 7.6 Stateless Agent Posture

- **Status:** ACCEPTED
- **Why accepted:** Persistent agent identity is outside AG1 scope per AGENT_GOVERNANCE_CONTRACT_V1.txt
- **Operational impact:** Agents do not maintain state across sessions; each invocation is independent
- **Escalation threshold:** If operational requirements demand persistent agent identity (requires SA escalation and architecture review)

## 7.7 No Dedicated Agent Governance Subdomain

- **Status:** ACCEPTED
- **Why accepted:** General signal hierarchy provides sufficient containment; separate subdomain is unnecessary for AG1
- **Operational impact:** Agent governance is handled by general governance and signal hierarchy
- **Escalation threshold:** If multi-agent coordination is operationalized (would require dedicated governance subdomain)
