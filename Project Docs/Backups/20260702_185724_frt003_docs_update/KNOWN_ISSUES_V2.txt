## ISSUE-S11-LARGE-DOC-TRANSFORM-TRUNCATION — AG1 Dependency Context Truncates Large Source Outputs Before Semantic Transforms

- **Root cause:** `tool_selection_agent.py` builds AG1 dependency context with `_safe_truncate()`, using `_MAX_DEPENDENCY_RESULT_CHARS = 800`. Large dependency outputs are reduced to ~750 characters plus literal `... [truncated]` before AG1/finalize_output sees them.
- **Impact:** MEDIUM-HIGH — `extract_key_points`, `summarize`, and `explain` over large local files or large webpages may operate only on the first excerpt of the source. Final output may be incomplete, overly short, or may echo literal `[truncated]`.
- **Current status:** ACTIVE / KNOWN LIMITATION.
- **Architectural layer:** Intelligence / capability routing / document transform layer.
- **Authority/contracts affected:** AGENT_GOVERNANCE_CONTRACT_V2, AGENT_CAPABILITY_ROUTING_CONTRACT_V2, PLANNING_COMPILER_CONTRACT_V2, STEP_IO_CONTRACT_V2.
- **Blocking:** Does NOT block FOUNDATION-RETOUCH-001 routing/mechanics closure. SHOULD block any claim of robust large-document semantic transform capability and must be owned before learning trains on large-document transform outcomes.
- **Evidence:**
  * FOUNDATION-RETOUCH-001 truncation audit found `read_file` stored the full `SYSTEM_STATE_V2.txt` output: 223,644 characters.
  * AG1 received only an ~800-character dependency excerpt.
  * Literal `[truncated]` was inserted by `_safe_truncate()` before AG1 saw the dependency content.
  * This is not GUI display truncation, not backend aggregation truncation, not read_file failure, and not formatter failure.
- **Clarification:**
  * `read_file` / `read_webpage` acquisition can be correct while semantic transform quality remains limited.
  * AG1 should not be made responsible for arbitrary large-document intelligence by simply raising the 800-character limit.
  * A proper fix likely requires document chunking, multi-pass summarization, retrieval/indexing, token-budget policy, or a dedicated document-transform capability/tool path.
- **Next action:** Sprint 11 foundation planning should classify and own a document-transform/chunking strategy before robust document intelligence or learning over document-transform outputs is claimed.
- **Explicitly not introduced:**
  * no code change in this doc update
  * no prompt change
  * no new agent
  * no learning/adaptation activation
  * no lifecycle/governance/system_entry/projection authority change

## ISSUE-SYNC-WEBSOCKET-PROJECTION-STALE-PANEL — WebSocket/Projection Panels Can Temporarily Diverge After Completion

- **Root cause:** After workflow completion, WebSocket event delivery and projection HTTP refresh may converge at different speeds across frontend panels. One panel (e.g., Execution Result) may show completed output while another panel (e.g., Plan/Projection view) still displays a stale blocked/waiting state because the projection snapshot has not yet caught up with the terminal event stream.
- **Impact:** LOW-MEDIUM — operator-facing projection/WebSocket consistency issue. Runtime authority unaffected. Execution result is correct. Temporary divergence is legal eventual-consistency behavior.
- **Current status:** ACTIVE OBSERVATION — NOT a runtime authority corruption.
- **Architectural layer:** LAYER 4 (Projection) / LAYER 8 (Transport)
- **Authority/contracts affected:** PROJECTION_CONTINUITY_CONTRACT_V1, OBSERVABILITY_AND_DASHBOARD_ARCHITECTURE_CONTRACT_V1
- **Blocking:** No — does not block FOUNDATION-RETOUCH-002 (MCP1, AIDER1, OPENHANDS1) closure.
- **Clarification:**
  * Observed during MCP1 GUI smoke after `Read https://example.com`.
  * One panel showed completed output while another Plan/projection surface still showed blocked/waiting state.
  * Runtime truth (backend execution result) was correct throughout.
  * This is an existing projection/WebSocket consistency observation, not a new regression introduced by FRT-002.
  * Projection/frontend remain non-authoritative.
  * Runtime truth supersedes projection interpretation.
  * Temporary divergence is legal eventual-consistency behavior; convergence failure is the actual defect condition.
  * Not a lifecycle authority corruption.
  * Not a governance corruption.
  * Not a system_entry bypass.
- **Next action:** Future observability/projection refinement, likely Sprint 13 or existing projection continuity work. Revisit if convergence permanently fails or if operator UX materially degrades.
