## 2. Current System Posture

**What exists:**
- Deterministic execution gateway (`system_entry`) with lifecycle authority, governance supremacy, and projection non-authority.
- Stable orchestration with pause/resume, retry, cancellation, and recovery.
- WebSocket live observability + polling/SSE fallback.
- Capability routing skeleton (arithmetic, document_local_read, web_read, semantic final-action). Semantic final-action routing/mechanics for `extract_key_points` are accepted; large-document transform quality remains limited by AG1 dependency-context truncation and is tracked separately.
- AG1 bounded tool-selection agent (advisory-only). AG1 remains the only active agent unless Sprint 11 explicitly opens bounded new agents.
- Operator-managed memory storage with inspection/edit/reset surface.
- Approval and notification baseline (backend-owned, frontend intent-only).
- LLM routing with OpenRouter support and budget guard.
- Partial baseline security layer: URL safety utility (ADOPT-002), path confinement utility (ADOPT-003), and backend tool policy enforcement (ADOPT-004) are implemented and tested. Approval/integration gaps remain: external-call approval gate (Sprint 14), local path user-control (ISSUE-103), GUI plan-mode surface (Sprint 13).
- FOUNDATION-RETOUCH-002 completed: reference-informed baseline retouch across six repos (Agentic Inbox, Hermes, Browser Use, MCP, Aider, OpenHands SDK). Baseline hardening implemented: tool visibility metadata (AI1), URL/path/web safety tests + cloud metadata IP deny floor (MCP1), file mutation tests + binary write guard (AIDER1), tool registry integrity + result-shape + policy metadata tests (OPENHANDS1). No reference runtime adopted. No Sprint 11 opened.

**What is missing:**
- Broad useful tool suite (not yet created; Sprint 11 foundation completion).
- Broad agent expansion (AG1 is the only active agent; Sprint 11 decides scope).
- Tool schema direction (Sprint 11 decision or blocker).
- Replacement/retirement of weak tool paths before learning (Sprint 11).
- Learning and preference adaptation (Sprint 12).
- Plan editing and workflow repair UX (Sprint 13).
- Privacy sensitivity classification and spend gates (Sprint 14).
- Sandbox and self-development path (Sprint 15).
- Production hardening (auth, CORS, CI, monitoring) (Sprint 16+).
- Coding assistant as a polished product capability (Sprint 15).
- Robust large-document semantic transforms (chunked/multi-pass summarize, explain, extract_key_points) are not implemented; AG1 dependency context currently truncates large source outputs before semantic finalization.

**What is next:**
- Return to Head Dev for FOUNDATION-RETOUCH-002 closure/approval.
- Decide whether FRT-002 baseline is sufficient to approve Sprint 11 gap list or whether Head Dev wants one more targeted audit.
- Resolve remaining Sprint 11 blockers: tool/capability gap list approval (FRT-002 evidence produced; approval pending) and tool schema direction if schema-dependent work is included. AGENT-001I-FIX1 is resolved for routing/mechanics; ISSUE-108 is rejected for cross-turn/bare-continuation inference scope. Large-document transform truncation is tracked as a Sprint 11 foundation issue if document intelligence is in scope.
- Open Sprint 11 only after blockers are resolved.
- Sprint 11 is Capability / Tool / Agent Foundation Completion, NOT learning.
- Current planning/DAG instability is the main reason Sprint 11 must happen before learning.
- Capabilities/tools/agents are the forward-build mechanism to reduce planner/resolver fragility.
- Keep architecture frozen.

## 8. Sub-Dev Working Rules

Bryan's working preferences:

- **Audit-first by default.** Understand before implementing.
- **One issue at a time.** Finish one before starting the next.
- **Single copyblock prompts.** Do not create Frankenstein prompts that merge multiple unrelated tasks.
- **No prompt changes without explicit flag.** If you change a prompt, flag it and get approval.
- **Docs updated at issue/session end.** Do not leave docs stale.
- **Manual GUI validation matters.** Automated tests are necessary but not sufficient. Bryan validates manually.
