# 🧠 VALIDATION RULES

---

## SUCCESS CRITERIA

A test PASSES ONLY if:

✔ Output is correct
✔ Execution path is valid
✔ No architectural violations occur

---

## FAILURE CRITERIA

A test FAILS if:

❌ system crashes
❌ exception escapes
❌ incorrect result returned
❌ chaining fails
❌ validation runs at wrong stage
❌ execution mutates arguments incorrectly

---

# 🚨 PHASE 2B LOCK REQUIREMENTS

ALL of the following MUST be true:

* ✔ Chaining ALWAYS succeeds
* ✔ PREVIOUS_RESULT passes validation as placeholder
* ✔ Chain resolution occurs DURING execution
* ✔ Execution does NOT modify arguments
* ✔ Deterministic output across runs

---

# 🔒 ARCHITECTURE ENFORCEMENT

Tests MUST ensure:

❌ Planner does NOT generate args
❌ Parser does NOT generate args
❌ Resolver is ONLY source of args
❌ Chain Resolver is ONLY source of chaining
❌ Execution is pure runtime

---

# ⚠️ IMPORTANT

Tests MUST NOT:

❌ allow partial success
❌ allow fallback-based correctness
❌ mask architectural violations

---

# 🔥 FINAL PRINCIPLE

Correct success WITH correct architecture:

→ system is LOCKED

Correct output with wrong architecture:

→ system is STILL BROKEN
