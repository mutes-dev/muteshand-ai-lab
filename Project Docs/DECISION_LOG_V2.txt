## PROJECTION + CONTINUITY

### Projection-Only Frontend Model
**Decision:** Frontend must be pure projection renderer. Must derive ALL state from authoritative projection only. Must NOT synthesize lifecycle truth.
**Reason:** Frontend ownership of lifecycle state (isExecuting, activeWorkflowId) caused authority drift.
**Status:** ACTIVE ARCHITECTURE RULE

### Projection Continuity Formalization
**Decision:** Projection continuity is eventual-consistency architecture. Temporary lag is valid. Divergence is a bug only when convergence fails.
**Reason:** Projection systems are transport/projection layers, not lifecycle authority.
**Status:** ACTIVE ARCHITECTURE RULE

### Derived Execution Artifact Reclassification
**Decision:** tool_call, scheduler snapshots, projection caches, and stream projections are mutable operational state. NOT semantic truth. MUST invalidate after semantic mutation.
**Reason:** tool_call persistence bug proved compiled artifacts can diverge from canonical semantic truth.
**Status:** ACTIVE ARCHITECTURE RULE

### Resume Continuity Model
**Decision:** Resume MUST continue same workflow, same projection lifecycle, same hydration lifecycle. Must NOT create new lifecycle authority or competing workflow identity.
**Reason:** Recreating projection ownership caused stale lifecycle states and hydration freezes.
**Status:** ACTIVE ARCHITECTURE RULE

## DEPENDENCY + EXECUTION

### Deterministic Dependency Resolver Migration
**Decision:** Replace LLM-based dependency resolver with deterministic regex parser.
**Reason:** LLM resolver introduced non-determinism and violated Architecture Law #3 (model-agnostic requirement).
**Tradeoff:** Loss of semantic inference. Planner must correctly encode dependencies.
**Status:** COMPLETE + VALIDATED

### Dependency State Authority Stabilization
**Decision:** execution_scheduler prioritizes authoritative live workflow step state over stale scheduler snapshots.
**Reason:** Stale snapshot state was causing false dependency blocking.
**Status:** COMPLETE + VALIDATED

### Parallel Runtime Thread Safety
**Decision:** Add threading locks to conflict_detector and trace_collector global singletons.
**Reason:** Concurrent workflow execution caused race conditions on global state.
**Tradeoff:** Locks provide safety without singleton refactor. Architectural debt deferred.
**Status:** COMPLETE + VALIDATED

### Hybrid Sync/Async Execution Model
**Decision:** Maintain synchronous orchestrator wrapped in async API thread executor.
**Reason:** Avoid full async refactor. Preserve deterministic execution. Maintain existing contracts.
**Tradeoff:** No progressive updates during resume. Polling-based streaming.
**Status:** ACCEPTED LIMITATION

## DURABILITY + RECOVERY

### Cold-Start Authority Inversion Elimination
**Decision:** Registry initialization routes through `_update_runtime_registry_only` with existence guard. Stale disk mirror cannot overwrite runtime state.
**Reason:** Cold start was allowing persisted state to overwrite authoritative runtime truth.
**Status:** COMPLETE + VALIDATED

### Stale ACTIVE Resurrection Prevention
**Decision:** `warm_registry_from_disk()` normalizes stale ACTIVE disk state to PENDING_RECOVERY on startup.
**Reason:** Crashed ACTIVE workflows were being resurrected as executable, violating lifecycle authority.
**Status:** COMPLETE + VALIDATED

### PENDING_RECOVERY State
**Decision:** Introduce transient registry-only state for crashed ACTIVE workflows. Blocks zombie-ACTIVE operations.
**Reason:** Need a quarantine state that signals "requires run_workflow re-entry" without claiming ACTIVE authority.
**Status:** COMPLETE + VALIDATED

### Projection Store Persistence
**Decision:** Persist latest projection state (not event history) with atomic writes. Validate restored state against runtime authority.
**Reason:** Preserve projection continuity across process restart without introducing replay architecture.
**Status:** COMPLETE + VALIDATED

### Durable Lifecycle Persistence Gap Accepted
**Decision:** Disk persistence remains non-authoritative. Runtime registry preserved as sole lifecycle authority.
**Reason:** Full durable authoritative persistence requires significant redesign. Current recovery discipline is operationally sufficient.
**Status:** ACCEPTED LIMITATION — future architecture candidate

- No architecture change required—only wording alignment with verified behavior
