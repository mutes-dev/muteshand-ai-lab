## 1. PARSER QUOTED STRING LIMITATION

Parser extracts numeric arguments and quoted strings.

### STATUS

✔ By design
⚠ Known limitation

### EXPLANATION

Quoted strings do not support escaping or nesting.
Complex string handling may have edge cases.

### ACTION

Future phases may enhance quoted string support while maintaining determinism.

## 2. PLANNER RULE-BASED LIMITATION

Planner uses simple keyword matching:

* substring detection
* " then " splitting
* TOOL_RULES lookup

### STATUS

✔ By design
⚠ Known limitation

### EXPLANATION

Deterministic behavior is enforced.
No NLP, no inference, no semantic understanding.

### ACTION

Planner Hardening phase will expand coverage while maintaining determinism.

## 3. LLM NON-DETERMINISM (CONTROLLED)

LLM output may vary between executions when enabled.

### STATUS

✔ Controlled via validation layer
⚠ Known limitation

### EXPLANATION

LLM is non-deterministic by nature.

System mitigates this via:

- strict prompt constraints
- JSON-only output requirement
- validation layer enforcement
- fail-safe fallback (passthrough)

### ACTION

Future phases may introduce:

- response caching
- retry strategies
- stricter prompt templates

**Issue:** Partial semantic validation exists at orchestrator level (intent validator).

**Details:**

* LLM-assisted and advisory only
* Does not affect deterministic execution
* Does not validate full reasoning
* Does not enforce execution truth

**Status:** NOT A BUG — Expected limitation for current phase

- Structural validation does not catch this

## 13. SYSTEM CANNOT VALIDATE CORRECT TOOL SELECTION

LLM selects tools — selection may be wrong.

### STATUS

⚠ Accepted limitation — Validator Layer required

### EXPLANATION

- LLM may select `add_numbers` for a subtraction request
- Structural validation does not catch this
- Intent validator (numeric consistency) partially mitigates but does not fully solve

### ACTION

Validator Layer must evaluate whether selected tool matches user intent.

---

## 14. SYSTEM CANNOT ENFORCE WHEN NO TOOL SHOULD BE USED

LLM may trigger tool calls for non-tool queries.

### STATUS

⚠ Accepted limitation — Validator Layer required

### EXPLANATION

- Natural language questions (definitions, explanations) may incorrectly trigger USE_TOOL:
- No mechanism exists to determine if tool use was appropriate
- LLM format guard only validates format — not appropriateness

### ACTION

Validator Layer must classify tool-required vs no-tool-required inputs.

---

## 15. MULTI-TOOL LLM OUTPUTS NOT REJECTED

LLM may output multiple USE_TOOL: calls. Only the first is used.

### STATUS

⚠ Known gap — PENDING

### EXPLANATION

- `llm_output.split("USE_TOOL:", 1)` extracts only the first tool call
- Additional tool calls are silently discarded
- No warning or retry is triggered

### ACTION

Add detection: if LLM output contains more than one USE_TOOL: prefix, reject and retry.

---

## 16. FORMATTER MAY PRODUCE INCORRECT OUTPUTS

Response formatter uses LLM — output is not trusted.

### STATUS

⚠ Known limitation — by design

### EXPLANATION

- `_format_tool_output` calls `ollama_llm` to convert raw output to human-readable text
- LLM may hallucinate or produce unrelated responses
- Formatter failure falls back to raw output (safe fallback exists)
- Formatted output is never validated for correctness

### ACTION

Formatter is advisory only. Future improvement: add confidence scoring or skip formatter for math results.

---

## 17. MEMORY SYSTEM CAN LEARN INCORRECT NOISE TOKENS

Execution memory learns from failure→success pairs but may learn valid tokens as "noise".

### STATUS

⚠ Known limitation

### EXPLANATION

- If LLM adds a word that happens to differ between attempts, it may be learned as a bad token
- Filters prevent numeric, quoted, and path tokens — but word tokens are still at risk
- Example: "hello" was learned as a bad token for `subtract_numbers`

### ACTION

Future improvement: require minimum usage_count threshold before applying a learned token.

---

## 18. EXTERNAL TOOLS MAY PRODUCE RUNTIME WARNINGS

Tools making external HTTP requests (web_search) may produce SSL or connection warnings.

### STATUS

⚠ Minor — cosmetic only

### EXPLANATION

- DuckDuckGo HTML scraping may trigger HTTPS redirect warnings
- Warnings appear in stdout but do not affect execution result

### ACTION

Suppress warnings or add explicit HTTPS handling in web_search tool.

## 🔴 HAND ISSUES — ORCHESTRATOR LAYER (NON-P0)

These are orchestrator-layer issues that do not affect core pipeline determinism.

---

### HAND ISSUE — STEP EXECUTION MODEL

Step performs multiple executions (retries), not single-call.

### STATUS

⚠ Accepted behavior — documented in ORCHESTRATOR_CONTRACT.txt

### EXPLANATION

- orchestrator_runtime.py implements governance-controlled retry (lines 269+)
- Step may trigger multiple system_entry calls when governance returns "retry"
- Governance decision determines retry vs failure vs continuation
- last_result updated only after successful validation

### ACTION

Retry behavior must be governed by governance decisions. Any implicit retry logic is considered drift.

---

### HAND ISSUE — CONTEXT PROPAGATION LIMITATIONS

Context not consistently enforced in non-tool steps.

### STATUS

⚠ Known limitation

### EXPLANATION

- Context injection (last_result) works for tool-execution paths
- Non-tool execution paths may not properly validate context usage
- Context is ephemeral — not persisted to workflow state until step completion

### ACTION

Monitor during chaining validation. Document edge cases.

---

### HAND ISSUE — NON-TOOL VALIDATION GAP

System does not validate correctness of non-tool outputs.

### STATUS

⚠ Known limitation

### EXPLANATION

- Validation focuses on tool-execution paths (USE_TOOL:)
- Non-tool LLM outputs lack semantic validation
- Response formatter (LLM-based) is not validated for correctness

### ACTION

Add non-tool output validation if required for production.

---

### HAND ISSUE — VALIDATION LAYER DRIFT

Validator provides advisory signals only. Governance determines retry behavior.

### STATUS

⚠ Requires alignment

### EXPLANATION

- intent_validator.py returns retry/accept recommendations (advisory only)
- Governance evaluates validator output and determines retry decisions
- Chain correction logic may skip contradiction checks
- Validator is beyond pure evaluation but MUST NOT determine execution path

Target:

- Validator is advisory only
- Governance controls retry + output

### ACTION

Align validation layer to advisory role. Document in ORCHESTRATOR_CONTRACT.txt.
