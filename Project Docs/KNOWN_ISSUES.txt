### STATUS

## 3. LLM NON-DETERMINISM (CONTROLLED)

LLM output may vary between executions when enabled.

### STATUS

✔ Controlled via validation layer
⚠ Known limitation

### EXPLANATION

LLM is non-deterministic by nature.

System mitigates this via:

- strict prompt constraints
- JSON-only output requirement
- validation layer enforcement
- fail-safe fallback (passthrough)

### ACTION

Future phases may introduce:

- response caching
- retry strategies
- stricter prompt templates

## 10. AGENT TOOL EXECUTION BYPASS

Agent tool execution (USE_TOOL: prefix) in agent_executor.py bypasses system_entry.

### STATUS

⚠ Known architectural gap — TEMPORARY DEVIATION

### EXPLANATION

- When input_data starts with "USE_TOOL:", agent_executor routes directly to tool_executor
- This does NOT route through system_entry → validation → execution pipeline
- Orchestrator-layer tools (tool_registry) are separate from core tools (tool_index)
- Core pipeline is not affected — only orchestrator-sandboxed tools are involved

### ACTION

Refactor agent tool execution to route through system_entry:
- Agent detects USE_TOOL: prefix
- Constructs system_entry-compatible input
- Routes through system_entry
- Returns result under agent output contract

Priority: HIGH — architectural compliance required before production use
