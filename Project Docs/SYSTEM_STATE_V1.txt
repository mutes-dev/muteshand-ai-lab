### CHECKPOINT SYSTEM (Phase 2C)

Step-level workflow state persistence for crash recovery and resume.

Implementation: `checkpoint_manager.py` — atomic write operations. Checkpoint saved AFTER step reaches terminal state (COMPLETED/FAILED/BLOCKED). Location: `system/checkpoints/<workflow_id>.json`.

Rules: Checkpoint failure does NOT affect execution. Observational only per architecture.

### PROJECT MEMORY PERSISTENCE (Phase 2D)

Long-term persistence of ACTIVE workflows across system restarts.

Implementation: `persistence.py` — JSON-based workflow storage. ACTIVE, BLOCKED, and PAUSED workflows persisted. Location: `system/persistence/workflows/<workflow_id>.json`.

Features: Save triggered on state transitions. Restore before execution loop entry. ACTIVE status normalized to PENDING on restore (re-execution ready). Cleanup after workflow COMPLETED.

Integration: Resume logic combines persistence + checkpoint. Enables full workflow recovery after system restart. Foundation for Phase 3 Global Memory System.

Capabilities: Multiple workflows execute concurrently. Each workflow runs in isolated thread context. Workflow lifecycle: QUEUED → ACTIVE → COMPLETED / FAILED. Non-blocking execution.

Constraints: BackgroundManager does NOT execute tools. BackgroundManager does NOT modify execution input. All execution routes through system_entry. Governance remains sole decision authority.
