## 1. Purpose

This contract defines tool/profile gating for the Planner-First, Tool-Gated Hybrid Architecture.

It specifies:
- Which tool profiles exist.
- How the planner and AG1 receive scoped tool catalogs.
- How capability routing may recommend a profile without replacing the planner.
- How the system rejects tools outside the active profile.

This contract does NOT own execution, lifecycle, governance, projection, or learning authority.

---

## 2. Core Architecture Decision

The Planner-First, Tool-Gated Hybrid Architecture is accepted.

Key implications:
- The planner is the primary workflow decision-maker for non-trivial workflows.
- Capability routing is a deterministic closed-form fast path and a tool/profile recommender.
- AG1 remains the only active runtime tool-selection agent.
- No new autonomous agents are introduced by this contract.

## 4. Profile Selection

### 4.1 Who may select a profile

- The capability_router may RECOMMEND a profile.
- The planner/compiler may CONFIRM or OVERRIDE the recommended profile.
- AG1 receives the profile selected by the planner/compiler.

### 4.2 Deterministic profile selection

Profile selection must be deterministic where possible:

- Explicit file read/list -> DocumentReadProfile
- Explicit summarize/explain/extract -> DocumentSummaryProfile
- Explicit URL read -> WebReadProfile
- Pure arithmetic/computation -> ComputeProfile
- Explicit file write/edit/append -> FileMutationProfile
- Uncertain or mixed-domain -> GeneralFallbackProfile

### 4.3 Profile overrides

- The planner may override a capability-recommended profile.
- The planner may fall back to GeneralFallbackProfile if uncertain.
- A profile override must be observable in trace metadata.

---

## 5. Scoped Tool Catalog

### 5.1 Planner catalog

When the planner emits a plan, it must receive a scoped tool catalog matching the active profile.

Rules:
- The catalog must include only tools allowed by the active profile.
- GeneralFallbackProfile may include the full production tool set.
- The planner may see profile metadata and tool families.

### 5.2 AG1 catalog

AG1 receives the same scoped profile as the planner unless the planner explicitly changes scope mid-workflow.

Rules:
- AG1 must select from the scoped catalog.
- If AG1 proposes a tool outside the catalog, the proposal must be rejected before system_entry.
- Rejection reason: `tool_not_in_profile_allowlist`.

### 5.3 Capability router catalog

The capability router may recommend a profile and emit candidate workflows using only that profile's allowed tools.

Capability-emitted workflows must still pass:
```text
planning compiler -> workflow validator -> runtime/governance/system_entry
```

---

## 6. Rejection Rules

### 6.1 Tool outside active profile

If a step or tool proposal uses a tool outside the active profile:
- The step must be rejected before execution.
- Rejection reason: `tool_not_in_profile_allowlist`.

### 6.2 Profile mismatch

If a capability-recommended profile conflicts with the planner's selected profile:
- The planner's profile takes precedence.
- The conflict must be recorded in trace metadata.

### 6.3 Future DocumentQAProfile misuse

Until DocumentQAProfile is formally defined and approved:
- Any document Q&A step must be rejected.
- `semantic_transform` `answer_question` must be rejected.
- Slice 007 Q&A behavior must be rejected.
