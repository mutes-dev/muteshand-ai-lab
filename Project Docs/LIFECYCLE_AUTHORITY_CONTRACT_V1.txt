# AI LAB — LIFECYCLE AUTHORITY CONTRACT V1

## PURPOSE

Defines the authoritative ownership model for workflow and step lifecycle state.

This contract ensures:

* single lifecycle truth
* deterministic lifecycle transitions
* prevention of authority fragmentation
* synchronization consistency across GUI, streams, projections, and runtime

Orchestration sequencing is governed separately by:
ORCHESTRATION_AND_EXECUTION_SEQUENCE_CONTRACT_V1

Mutation legality is governed separately by:
MUTATION_LEGALITY_AND_RUNTIME_ISOLATION_CONTRACT_V1

Persistence semantics are governed separately by:
PERSISTENCE_AND_DURABILITY_CONTRACT_V1

Runtime coordination is governed separately by:
RUNTIME_REGISTRY_AND_EXECUTION_COORDINATION_CONTRACT_V1

Execution identity and replay semantics are governed separately by:
EXECUTION_IDENTITY_AND_REPLAY_CONTRACT_V1

Workflow Studio operational mutation semantics are governed by:
WORKFLOW_STUDIO_AND_OPERATIONAL_MUTATION_CONTRACT_V1

Workflow cancellation and terminalization semantics are governed by:
WORKFLOW_CANCELLATION_AND_TERMINALIZATION_CONTRACT_V1

---

## CORE PRINCIPLE

Lifecycle truth MUST exist in exactly ONE authoritative layer.

All other layers:

* consume
* mirror
* project
* render

But MUST NOT originate lifecycle truth.

---

# 1. AUTHORITATIVE OWNERSHIP

The Lifecycle Authority Layer owns:

* workflow lifecycle state
* step lifecycle state
* lifecycle transition validation
* lifecycle transition commits
* lifecycle consistency guarantees

### WORKFLOW EXISTENCE AUTHORITY

Lifecycle Authority governs:

* canonical workflow existence
* canonical workflow identity continuity
* workflow lifecycle ownership

Workflow identity continuity MUST remain stable across:

* restart
* reconnect
* hydration
* projection regeneration
* stream rebuild

Workflow existence MUST NOT be inferred from:

* projections
* streams
* frontend state
* hydration state

---

## VALID AUTHORITATIVE STATES

Workflow:

* QUEUED
* ACTIVE
* PAUSED
* BLOCKED
* COMPLETED
* FAILED

Step:

* PENDING
* ACTIVE
* BLOCKED
* COMPLETED
* FAILED

---

## RECOVERABLE VS IMMUTABLE TERMINAL DISTINCTION

Immutable Terminal States:

* COMPLETED
* CANCELLED

Immutable terminal states:

* do NOT support retry
* do NOT support continuation
* do NOT support structural mutation
* MAY support observability and inspection

Recoverable Terminal States:

* FAILED
* BLOCKED (future)

Recoverable terminal states MAY support:

* retry (creates NEW execution lineage)
* reconciliation (future)
* adaptive continuation (future)

Terminal state classification is governed by:
WORKFLOW_CANCELLATION_AND_TERMINALIZATION_CONTRACT_V1

## FAILED LIFECYCLE SEMANTICS CLARIFICATION

FAILED is:
recoverable terminal state.

FAILED workflows MAY be retried under:

* mutation legality rules
* execution identity isolation rules
* runtime coordination rules

Retry for FAILED workflows:

* creates NEW execution lineage
* is NOT stale execution continuation
* is NOT terminal state reversal

Retry does NOT:

* resurrect stale execution
* continue previous execution context
* rewind lifecycle state

## CANCELLATION LIFECYCLE CONVERGENCE GUARANTEES

Cancellation creates:
terminalized execution lineage.

Cancellation is:
authority-coordinated termination.

Cancellation commits terminalization BEFORE:
downstream synchronization per ORCHESTRATION_AND_EXECUTION_SEQUENCE_CONTRACT_V1.

Projection sync failure does NOT block lifecycle terminalization.

Stream sync failure does NOT block lifecycle terminalization.

Lifecycle Authority remains independent from synchronization success or failure.

Cancellation semantics are governed by:
WORKFLOW_CANCELLATION_AND_TERMINALIZATION_CONTRACT_V1

---

# 2. WRITE AUTHORITY

ONLY the Lifecycle Authority Layer may:

* commit lifecycle transitions
* mutate workflow lifecycle state
* mutate step lifecycle state

No other layer may directly modify lifecycle state.

---

# 3. READ AUTHORITY

All lifecycle reads MUST originate from Lifecycle Authority.

Consumers MAY cache or project state temporarily, but:

* projected state is NOT authoritative
* cached state is NOT authoritative

### WORKFLOW ENUMERATION RULES

Workflow enumeration MUST originate from authoritative workflow identity state.

Frontend MAY:

* render workflow lists
* render workflow selectors
* maintain UI selection state

Frontend MUST NOT:

* infer authoritative workflow existence
* synthesize workflow identity
* assume singleton workflow ownership

---

# 4. ORCHESTRATOR RESPONSIBILITY

Orchestrator MAY:

* request lifecycle transitions
* react to lifecycle state
* coordinate execution

Orchestrator MUST NOT:

* directly mutate lifecycle state
* synthesize lifecycle truth

---

# 5. GUI RESPONSIBILITY

GUI MAY:

* render lifecycle state
* display projections
* request lifecycle actions

GUI MUST NOT:

* infer lifecycle truth
* synthesize lifecycle state
* originate lifecycle transitions

---

# 6. STREAM RESPONSIBILITY

Streams MAY:

* transport lifecycle events
* mirror lifecycle updates

Streams MUST NOT:

* originate lifecycle state
* reconcile authoritative lifecycle truth

---

# 7. PROJECTION RESPONSIBILITY

Projection and polling systems MAY:

* build read models
* cache lifecycle snapshots
* support hydration and rendering

Projection systems MUST NOT:

* infer lifecycle transitions
* repair lifecycle divergence
* overwrite authoritative lifecycle state

---

# 8. TRANSITION VALIDATION

All lifecycle transitions MUST:

* pass through Lifecycle Authority
* obey STATE_TRANSITIONS_CONTRACT_V1
* be validated before commit

Invalid transitions MUST be rejected.

---

# 9. CONSISTENCY GUARANTEE

Lifecycle Authority MUST guarantee:

* valid state combinations
* synchronized workflow/step relationships
* deterministic transition ordering

---

# 10. SYNCHRONIZATION MODEL

Lifecycle Authority acts as:

* authoritative lifecycle source
* synchronization boundary
* transition commit layer

Other systems synchronize FROM this layer.

Lifecycle commits occur BEFORE downstream synchronization per:
ORCHESTRATION_AND_EXECUTION_SEQUENCE_CONTRACT_V1

Lifecycle authority is independent from synchronization success or failure.

Downstream sync failure does NOT invalidate lifecycle commits.

Projection sync failure does NOT block lifecycle terminalization.

Stream sync failure does NOT block lifecycle terminalization.

Lifecycle authority obeys orchestration sequencing contracts per:
ORCHESTRATION_AND_EXECUTION_SEQUENCE_CONTRACT_V1

---

## CONTINUITY BOUNDARY

Lifecycle Authority owns lifecycle truth ONLY.

Projection continuity behavior is governed separately by:

PROJECTION_CONTINUITY_CONTRACT_V1

Lifecycle Authority does NOT own:

* projection merge semantics
* hydration continuity
* event accumulation
* rendering continuity

## CONVERGENCE RELATIONSHIP

Lifecycle Authority convergence sequencing is governed separately by:

ORCHESTRATION_AND_EXECUTION_SEQUENCE_CONTRACT_V1

Recovery reconstruction follows:
PERSISTENCE_AND_DURABILITY_CONTRACT_V1

Lifecycle Authority owns:
authoritative lifecycle truth.

Lifecycle Authority does NOT own:

* projection sequencing
* stream sequencing
* hydration sequencing
* restart choreography
* execution reconstruction
* execution replay

Lifecycle Authority remains independent from execution reconstruction.

Lifecycle Authority does NOT reconstruct execution replay.

Execution reconstruction is governed by:
RUNTIME_REGISTRY_AND_EXECUTION_COORDINATION_CONTRACT_V1

Replay semantics are governed by:
EXECUTION_IDENTITY_AND_REPLAY_CONTRACT_V1

---

# 11. PROHIBITED PATTERNS

The following are prohibited outside Lifecycle Authority:

* local workflow.status mutation
* projection-derived lifecycle truth
* frontend lifecycle synthesis
* stream-based lifecycle reconciliation
* uncontrolled lifecycle writes

---

# 12. FAILURE MODEL

If lifecycle inconsistency occurs:

* Lifecycle Authority state remains source of truth
* projections MUST reconcile to authority
* GUI MUST refresh from authority
* streams MUST not override authority
