## DECISION — TRACE REPLACES STEPS IN OUTPUT

STATUS: ACTIVE

RULE:

Execution output uses `trace` for observability instead of `steps`.

Implementation:

- system_entry._normalize_output() strips `steps` field
- Debug trace from planner captured and added as `trace` field
- Contract format: {"status": "success", "result": <value>, "trace": [...]}

REASON:

- Aligns with observability requirement
- Separates execution contract from trace data
- Reflects actual system behavior

## DECISION — EXECUTION FAILURE PROPAGATION

STATUS: ACTIVE

RULE:

Execution layer MUST propagate tool-level failure objects directly.

Implementation:

- Check if tool output is dict with status="failure"
- If true: return failure object immediately
- If false: wrap in success response as normal

Rationale:

- prevents nested failure structures
- enforces consistent failure contract
- aligns execution with system-wide error handling
