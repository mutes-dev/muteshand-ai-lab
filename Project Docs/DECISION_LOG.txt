## 2026-05 — Deterministic Dependency Resolver Migration

Decision:
Replace LLM-based dependency resolver with deterministic parser.

Reason:

- LLM resolver introduced non-determinism and instability
- Dependency correctness inconsistent across runs
- Performance overhead (second LLM call per workflow)
- Architectural violation (intelligence in execution-adjacent layer)

Implementation:

- Removed LLM dependency resolver completely
- Removed normalization layer
- Introduced deterministic regex-based parser
- Planner updated to emit explicit step_X references

Impact:

- Dependency resolution is now deterministic
- Execution behavior is predictable
- Performance improved (no second LLM call)
- Dependency correctness now depends solely on planner output

Tradeoff:

- Loss of semantic inference
- Planner must correctly encode dependencies

Status: COMPLETE + VALIDATED

## 2026-05 — Authoritative Runtime + Projection Architecture Clarification

Decision:
Formalize runtime registry as sole lifecycle authority.

Clarifications:
- Frontend is projection-only
- Polling is transport-only
- Stream registry is projection cache only
- Executors are cooperative only
- Resume continues existing lifecycle
- Projection continuity must persist across pause/resume

Reason:
Pause/resume stabilization exposed authority drift and competing lifecycle ownership.

Architecture audit (PHASE X) verified:
- run_workflow mutates workflow["status"] directly instead of updating _workflow_state_registry
- _stream_registry stores status (lifecycle truth) instead of being cache/projection only
- Frontend synthesizes isExecuting and activeWorkflowId state not derived from authoritative projection
- Multiple sources of lifecycle truth exist with no conflict resolution

Key Insight:
Multiple workflows are valid.
Multiple authorities per workflow are NOT valid.

Impact:
- Future GUI architecture constrained to projection-only model
- Future websocket migration constrained to transport-only model
- Projection ownership formalized
- Lifecycle semantics formalized
- Runtime authority codified as sole source of truth

ACTIVE ARCHITECTURE RULE
