### D. WHY WRAPPING EXISTS

**Historical Reason:**
- Early architecture separated "workflow status" from "execution result"
- Workflow could be COMPLETED but execution could fail
- Wrapper allowed returning both workflow-level and execution-level status

**Current Reality:**
- `run_workflow()` already handles failure cases separately (lines 571-572, 574-575)
- Wrapper creates double-nesting: `result.result.result` to access actual value
- Trace inclusion violates INTERFACE_CONTRACT_V1
