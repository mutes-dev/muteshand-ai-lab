### SPRINT-11-PROJECTION-PLAN-STALE-STATUS-FIX

**Status:** ACCEPTED / COMPLETE + TESTED + BRYAN GUI VALIDATED.

**Root cause:**
- Terminal projection emitted correctly while in-memory projection store exists.
- After completion, projection_manager.remove_workflow removes the in-memory projection store.
- GET /projection/{workflow_id} falls back to workflows.json.
- Synthetic projection built from persisted workflow was missing projection_state.
- Frontend rejected the lower-version synthetic projection because incomingIsTerminal required projection_state === "TERMINAL".

### Task Hub / History Cross-Lock Deadlock Fix

**Status:** FIXED + VALIDATED.

**Classification:** Separate backend incident discovered during PDIAG-005 manual smoke. NOT caused by PDIAG-005 `false_success_analysis`.

**Root cause:** Pre-existing AB-BA cross-lock deadlock in `ai_lab_gui/backend/api.py`:
- `get_authoritative_workflows()` held `_workflow_state_lock` while iterating the registry, then acquired `_stream_registry_lock` inside the same block for QUEUED workflows.
- `_run_workflow_wrapper()` held `_stream_registry_lock` after execution completion, then called `_get_workflow_state()` which acquires `_workflow_state_lock`.
- Repeated Task Hub polling (every 3 s) exhausted the 4-worker `ThreadPoolExecutor`, causing both `/workflows/authoritative` and `/workflows/historical` to hang indefinitely.

**Fix applied:**
- `get_authoritative_workflows()` now copies `_workflow_state_registry` snapshot under `_workflow_state_lock`, releases the lock, then iterates the snapshot.
- `_stream_registry_lock` is acquired only after `_workflow_state_lock` is released.
- No broad Task Hub/History refactor.
- No workflow files deleted.
- No PDIAG-005 detector changes.
- No lifecycle/projection/governance semantic changes.
