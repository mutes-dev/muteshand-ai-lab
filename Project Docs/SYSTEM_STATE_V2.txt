### Verified Foundations — Phase 3F-XA Stabilization (May 2026)

**Authoritative Runtime Lifecycle Ownership Stabilized:**

* All lifecycle writes route through `request_step_transition` or `_update_workflow_state`

**Cold-Start Authority Inversion Eliminated:**

* Registry initialization routed through `_update_runtime_registry_only` with existence guard
* Stale disk mirror cannot overwrite authoritative runtime state during cold start

**Stale ACTIVE Resurrection Prevented:**

* `warm_registry_from_disk()` normalizes stale ACTIVE disk state to PENDING_RECOVERY
* 31 real stale ACTIVE workflows normalized during testing

**Deterministic Warm Registry Restoration:**

* Proactive registry population from disk on every startup
* Restoration is deterministic and failure-isolated

**Checkpoint Authority Alignment:**

* `checkpoint_manager._extract_checkpoint_data` sources workflow_status from `_get_workflow_state` (registry authority)
* Falls back to compatibility mirror only if registry unavailable

**bg_id Continuity Persistence:**

* `bg_id_map.py` implements atomic persistence for bg_id → workflow_id mapping
* API startup restores persisted mappings into stream registry

**Projection Version Monotonicity Persistence:**

* `projection_manager.py` persists projection_version counters to disk
* Version counter resumes above last persisted value after restart

**PENDING_RECOVERY State Introduced:**

* Transient registry-only state for crashed ACTIVE workflows
* Blocks zombie-ACTIVE operations

### Verified Foundations — Phase 3F-XB Stabilization (May 2026)

**Projection Store Persistence Implemented:**

* Atomic writes using tempfile → os.replace pattern
* Persisted: latest projection, projection_state, continuity_anchor_version, stale_rejection_count

**Deterministic Startup Projection Restoration:**

* `warm_stores_from_disk()` restores persisted projection stores on API startup
* Validates restored state against runtime authority
* Stale persisted projections rejected (runtime truth wins)

**Projection Continuity Preserved Across Restart:**

* Latest projection state survives process restart
* Projection lifecycle state preserved (ACTIVE, TERMINAL, etc.)

**Stale Persisted Projection Rejection Implemented:**

* `load_from_persisted()` validates persisted_version against current_version
* Rejects persisted state if older than current runtime state

**Terminal Projection Protection Preserved:**

* `emit_lifecycle_changed()` triggers cleanup for COMPLETED/FAILED workflows
* Terminal projections cannot be overwritten by non-terminal projections

**Hydration Continuity Improved:**

* Frontend can reconnect to in-progress workflows after restart
* Projection restoration provides continuity anchor for hydration validation

**No Replay Architecture Introduced:**

* Only latest projection state persisted, not event history
* No event sourcing infrastructure added
* No replay engine implemented
