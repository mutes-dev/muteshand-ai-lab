## PURPOSE

# 🧪 TEST PRINCIPLES

Harness tests:

* behavior
* invariants
* contracts

NOT implementation details

# 🧱 LAYERED HARNESS MODEL

The harness must support testing at different system layers.

Harness MUST NOT assume full system availability.

Harness validates the COMPLETE pipeline:

Planner → Parser → Resolver → Entry → Validation → Execution

# 🔍 REQUIRED TEST TYPES

---

## 0. SYSTEM_ENTRY TEST (PRIMARY)

Harness MUST use system_entry as the ONLY execution path.

All tests execute via:

```python
result = system_entry(input_text)
```

NO direct layer testing.
NO bypassing system_entry.

---

Same input → same output

Run:

* 3 times minimum

FAIL if:

* outputs differ

## 2. CONTRACT TEST

Verify:

* input format accepted
* output format matches contract

FAIL if:

* missing fields
* incorrect structure

---

## 6. PARSER CONTRACT TEST

Verify:

* planner output is correctly translated
* numeric arguments extracted deterministically
* failure passthrough preserved

FAIL if:

* parser modifies failure object
* parser introduces non-numeric args
* parser performs inference

---

## 6. RESOLVER CONTRACT TEST

Verify:

* injects PREVIOUS_RESULT deterministically
* does NOT infer values
* does NOT reorder arguments
* does NOT access registry
* does NOT access execution results

FAIL if:

* resolver performs inference
* resolver modifies argument count beyond PREVIOUS_RESULT injection
* resolver accesses external data

---

## 3. EXECUTION TEST

Verify:

* correct result for known inputs

Example:

* add 2 and 3 → 5

---

## 4. FAILURE TEST

Verify:

* invalid input produces failure
* system does NOT attempt execution

---

## 5. FAILURE CONTRACT VALIDATION

Verify that ALL failure outputs strictly match the execution contract.

Requirements:

- Output MUST include:
  - "status"
  - "reason"

- "status" MUST equal "failure"
- "reason" MUST be a non-empty string

FAIL if:

- "reason" field is missing
- "reason" is not a string
- "reason" is empty
- "status" is not "failure"

- No LLM dependency
- deterministic behavior required

- validate deterministic behavior in SAFE MODE
- validate contract compliance in INTELLIGENT MODE

# SUBSET MATCHING LOGIC

Harness uses subset matching for test validation:

```python
if isinstance(expected, list) and isinstance(result, dict) and "steps" in result:
    comparison_target = result["steps"]
else:
    comparison_target = result

def is_subset_match(actual, expected):
    if not isinstance(expected, dict):
        return actual == expected
    for key, expected_value in expected.items():
        if key not in actual:
            return False
        actual_value = actual[key]
        if isinstance(expected_value, dict):
            if not is_subset_match(actual_value, expected_value):
                return False
        elif isinstance(expected_value, list):
            if actual_value != expected_value:
                return False
        elif actual_value != expected_value:
            return False
    return True

if not is_subset_match(comparison_target, expected):
    FAIL
else:
    PASS
```

Expected fields must match.
Extra fields in actual are allowed.
