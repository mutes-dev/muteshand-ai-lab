  - "reason"

- "reason" MUST be a non-empty string

- "reason" field is missing
- "reason" is not a string
- "reason" is empty
- "status" is not "failure"

# STRICT SCHEMA VALIDATION (HARD GATE)

Harness enforces STRICT contract validation:

```python
def validate_strict_contract(result):
    # MUST be dict
    if not isinstance(result, dict):
        return False, "result is not a dict"
    
    # MUST have status field
    if "status" not in result:
        return False, "missing status field"
    
    # Success: MUST have result field, MUST NOT have reason
    if result["status"] == "success":
        if "result" not in result:
            return False, "success missing result"
        if "reason" in result:
            return False, "success has reason field"
        if len(result) != 2:
            return False, "success has extra fields"
        return True, None
    
    # Failure: MUST have reason field, MUST NOT have result
    if result["status"] == "failure":
        if "reason" not in result:
            return False, "failure missing reason"
        if "result" in result:
            return False, "failure has result field"
        if len(result) != 2:
            return False, "failure has extra fields"
        return True, None
    
    return False, "invalid status value"
```

Rules:
- EXACTLY 2 fields allowed: status + result (success) or status + reason (failure)
- NO extra fields allowed (no trace, no steps, no metadata)

## ⚠️ LIMITATION — SEMANTIC VALIDATION

Harness validates:

✔ structure (contract fields, types)
✔ determinism (same input → same output)
✔ contract compliance (strict schema enforcement)
✔ argument count and type correctness

Harness does NOT validate:

❌ reasoning correctness (was the right answer produced?)
❌ tool correctness (was the right tool selected?)
❌ tool necessity (should a tool have been used at all?)
❌ output relevance (does formatted output match the question?)

These limitations are ACCEPTED for the current phase.
The harness validates STRUCTURAL correctness only.
Semantic validation partially implemented at orchestrator level (intent validator), not covered by harness.

---

## ⚠️ LIMITATION — ORCHESTRATOR LAYER

Harness validates execution only (system_entry)

Does NOT validate:

* final output selection logic
* governance decisions
* validator influence on retry or escalation

Validator is NOT authoritative.

Validator enforces contract structure only.
It does NOT determine execution correctness or workflow decisions.
