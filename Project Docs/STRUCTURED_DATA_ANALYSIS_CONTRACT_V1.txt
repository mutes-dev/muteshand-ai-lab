1. Purpose
------------------------------------------------------------

StructuredDataAnalysisProfile governs bounded deterministic local CSV/XLSX analysis.

The profile is for one-file, one-table/worksheet, bounded structured-data analysis where the input data has already been acquired or can be acquired through approved local readers.

The profile supports deterministic structured-data operations such as:

- row count;
- max;
- min;
- sum;
- average;
- deterministic associated-row lookup for max/min only when supported by evidence and approved implementation design.

The profile is not a broad spreadsheet intelligence system.

29. F5 AI-FIRST STRUCTURED DATA ADVISORY MODE DECISION — 2026-07-14
------------------------------------------------------------

Decision package title:
F5 AI-FIRST STRUCTURED DATA ADVISORY MODE DECISION

Executive verdict:
AI_FIRST_STRUCTURED_DATA_REALIGNMENT_REQUIRED

Decision summary:
F5 must not become deterministic-only.

The F5R realignment correctly rejected flat positional analyze_table expansion.
This amendment adds the complementary constraint: the system must not overcorrect into
deterministic-only product behavior that refuses to attempt anything outside a narrow grammar.

Bryan's product goal is an AI system that can attempt broad useful structured-data reasoning
where safe, while clearly separating verified results from advisory outputs.

StructuredDataAnalysisCapability remains the structured-data domain owner.
Its role is to mediate between:

- planner/AG1 reasoning;
- deterministic structured-data tools;
- evidence/result verification;
- advisory/unverified output classification;
- safe unsupported outcomes.

SA explicitly rejects both extremes:

Rejected extreme 1:
One giant deterministic flat positional analyze_table tool that slowly becomes the
structured-data planner.

Rejected extreme 2:
Deterministic-only product behavior where the system refuses to attempt anything outside a
narrow grammar even when a safe advisory answer is possible.

Correct model:
Attempt with AI where safe.
Verify deterministically where possible.
Label trust level honestly.
Block only when unsafe, unavailable, ambiguous, or authority-risky.

29.1 Trust classification
------------------------------------------------------------

F5 architecture must support four output classes:

1. verified

Meaning:
- deterministic tool-backed;
- evidence refs available (table/sheet/row/column/cell);
- result may be presented as computed and grounded.

Allowed example wording:
- "The verified maximum Score is 91."
- "Rows matching Score > 85 are rows 2 and 4."
Only when deterministic evidence supports the result.

2. advisory

Meaning:
- AI-generated reasoning from bounded available context;
- not deterministically verified;
- must be visibly labeled as advisory/unverified;
- cannot become execution truth;
- cannot feed learning unless Bryan explicitly accepts it.

Allowed example wording:
- "Advisory interpretation from the visible table preview: ..."
- "This is not a verified computation."

Advisory output must not masquerade as verified computation.
Advisory mode is a design requirement, not yet runtime-active.

3. unsupported

Meaning:
- request cannot safely be attempted or answered;
- would require unavailable data, hidden access, forbidden execution, unsafe mutation,
  formula/macro execution, high-risk claim, or unsupported authority.

4. ambiguous

Meaning:
- table/sheet/column/request cannot be resolved clearly enough to proceed;
- system must ask for clarification or return an ambiguity response instead of guessing.

------------------------------------------------------------
29.2 Deterministic tools are verification primitives, not the product brain
------------------------------------------------------------

Deterministic tools are trusted execution / verification primitives.

They must not become the sole decision-making layer for structured-data responses.

The two valid positive-output modes are:

A. VERIFIED STRUCTURED-DATA RESULT

Used when the operation is supported by deterministic tooling and evidence refs.

Examples of operations eligible for verified output:
- count rows;
- max;
- min;
- sum;
- average;
- deterministic filter;
- deterministic sort/rank if later approved;
- associated row/entity if grounded;
- table/cell/row/column evidence-backed output.

B. AI ADVISORY STRUCTURED-DATA ANALYSIS

Used when planner/AG1 can inspect bounded available table context and produce a useful
response, but no deterministic verification path exists.

Output must be labeled:
- advisory;
- unverified;
- not execution truth;
- not deterministic computation;
- not safe for learning unless Bryan explicitly accepts it.
